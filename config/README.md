# config/

Тут на сервері з'являються службові файли, яких немає в git:

- `users.php` — облікові записи адмінки (паролі лише у вигляді хешів);
- `setup-token.php` — одноразовий код для першого входу, зникає після створення облікового запису;
- `login-attempts.php` — лічильник невдалих спроб входу;
- `login-log.php` — журнал входів (останні 60 вдалих і 60 невдалих спроб);
- `sessions/` — відкриті сеанси адмінки;
- `debug` — якщо створити порожній файл з такою назвою, сайт показуватиме попередження PHP (лише для налагодження).

Тека закрита з інтернету через `.htaccess`. Додатково всі файли з даними мають розширення `.php`
і починаються з команди «вийти», тому навіть на сервері, який не зважає на `.htaccess` (nginx),
за прямим посиланням вони нічого не показують.

На хостинг із цієї теки переносяться лише `.htaccess` і цей файл. Локальні `users.php`,
`local-credentials.php` і `sessions/` на сервер не завантажуються: там обліковий запис створюється заново
(архів без них збирає `python3 tools/pack_for_hosting.py`).
