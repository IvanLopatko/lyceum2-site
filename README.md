# Сайт Біляївського ліцею №2

Власний сайт ліцею без WordPress і без бази даних: PHP 8.1+, вміст у JSON-файлах, адмінка для редагування.

**Подивитися:** статична копія на GitHub Pages (посилання — у розділі «About» праворуч). Адмінки й пошуку в копії немає; вона закрита від пошуковиків і має плашку «Зразок».

## Як влаштовано

| Тека | Що там |
|---|---|
| `index.php` | Єдина точка входу: сайт і адмінка (`/admin/`) |
| `app/` | Код: маршрути, шаблони, логіка строків за ст. 30, адмінка |
| `content/` | Увесь вміст: `pages/` (сторінка = файл), `news/` (новина = файл), `documents.json`, `staff.json`, `clubs.json`, `settings.json`, `profile-plan.json` |
| `uploads/` | Фото й PDF |
| `assets/` | Стилі, скрипти, шрифти (локально), значки, ілюстрації |
| `config/` | На сервері: облікові записи адмінки, сесії. **Не в git** |
| `docs/` | Статична копія для GitHub Pages |
| `tools/` | Перенесення з WordPress, експорт статичної копії, локальний запуск |

Сторінки складаються з блоків: абзац, заголовок, список, кроки, хронологія, картки, цифри, питання-відповіді, таблиця, виноска, кнопки, цитата, порівняння, міфи і факти, галерея та «живі» блоки (реєстр документів, люди, план профільної школи, відлік днів, контакти тощо). Усі редагуються мишкою в адмінці.

## Адмінка

- Вхід: `/admin/`. Паролі зберігаються лише як хеш, після 5 невдалих спроб — пауза 15 хвилин, усі форми захищені від підробки (CSRF).
- Розділи: огляд (строки документів, зразкові дані), сторінки, новини з фото, документи з PDF, кадри з фото, гуртки, налаштування (контакти, цифри, «Сьогодні в ліцеї», відповідальні), обліковий запис (пароль, доступи для редакторів).
- Фото при завантаженні зменшуються до 1600 px і перекодовуються; PDF перевіряються за вмістом.
- Перед кожною правкою попередня версія файлу кладеться в `content/.history/` (30 останніх).

## Запуск локально

З PHP 8.1+:

```bash
php -S 127.0.0.1:9600 tools/dev-router.php
```

Без PHP — через Node.js:

```bash
npx @wp-playground/cli@latest server --port 9600 --mount-dir "$(pwd)" /wordpress --wordpress-install-mode=do-not-attempt-installing --skip-sqlite-setup
```

## Перенесення на хостинг

1. Хостинг з PHP 8.1+ (розширення `gd`, `mbstring`, `json`, `fileinfo`) і **увімкненим HTTPS** (SSL-сертифікат; на більшості хостингів безкоштовний). Найпростіше — Apache або LiteSpeed: правила з `.htaccess` запрацюють самі.
2. Зібрати чистий архів для завантаження: `python3 tools/pack_for_hosting.py`. У ньому є все потрібне й немає того, чого на сервері бути не повинно: локальних облікових записів і паролів з `config/`, теки `.git`, статичної копії `docs/`, робочих скриптів `tools/`, історії правок і кошика. **Не завантажуйте на хостинг теку проєкту як є** — разом з нею туди потрапить локальний пароль.
3. Розпакувати архів у корінь сайту (через файловий менеджер хостингу або FTP).
4. Відкрити `https://…/admin/` — сайт попросить код із файлу `config/setup-token.php` (другий рядок файлу; його видно лише через файловий менеджер хостингу) і створить перший обліковий запис. Пароль — новий, не той, що був на локальній копії.
5. У «Налаштуваннях» вказати адресу сайту (`https://…`) — вона потрібна для карти сайту.
6. У файлі `.htaccess` розкоментувати блок «Завжди https» (три рядки), щоб сайт сам перекидав відвідувачів на зашифровану адресу.
7. Замінити зразкові тексти й прибрати зразкові записи кнопкою на огляді адмінки. Поки на сайті є зразкове і ввімкнено смугу «Зразок сайту», він сам закритий від пошуковиків (`robots.txt` і позначка `noindex`). Коли зразкового не лишиться, сайт відкриється, а `/sitemap.xml` віддасть карту сайту.

### Якщо хостинг на nginx

nginx не читає `.htaccess`. Адмінка сама перевіряє це і показує червоне попередження на «Огляді», якщо службові теки відкриті. У налаштування сайту треба додати:

```nginx
location ~ ^/(app|content|config|tools|docs)(/|$) { deny all; }
location ~ /\.(?!well-known) { deny all; }
location ~* ^/uploads/.*\.(php|phtml|phar|pl|py|cgi|sh)$ { deny all; }
location / { try_files $uri $uri/ /index.php?$args; }
```

## Безпека

Що вже зроблено в коді:

- **Вхід.** Паролі зберігаються лише як хеші (bcrypt). Після 5 невдалих спроб з однієї адреси вхід блокується на 15 хвилин. Пароль — від 10 символів, з літерами й цифрами; «слово й цифри» на кшталт `Liceum2026` чи логін із цифрами не приймаються. Сеанс закінчується після 4 годин бездіяльності; зміна пароля завершує всі інші сеанси.
- **Журнал входів.** На «Огляді» видно ваш попередній вхід, у розділі «Обліковий запис» — останні входи й невдалі спроби.
- **Ролі.** Редактор працює зі сторінками, новинами, документами, кадрами й гуртками. Налаштування, доступи, прибирання зразків і блок «HTML» — лише адміністратор.
- **Форми.** Кожна дія в адмінці захищена одноразовим ключем сеансу (CSRF); у текстах лишаються тільки дозволені теги, посилання — лише звичайні адреси.
- **Файли.** Фото перекодовуються (втрачають приховані дані й будь-який вбудований код), PDF перевіряються за вмістом, імена файлів сайт дає сам. Видалений файл одразу зникає із сайту й 30 днів лежить у закритому кошику.
- **Службові теки.** `app/`, `content/`, `config/`, `tools/` закриті правилами `.htaccess`. На випадок, якщо сервер цих правил не виконує: файли з `config/` і `app/` за прямим посиланням нічого не показують, а історія правок і кошик лежать у підтеках з випадковою назвою.
- **Браузер.** Сторінки забороняють вбудовувати себе в чужі сайти й виконувати сторонні скрипти (заголовок Content-Security-Policy). Тому в блоці «HTML» працюють `<iframe>` з YouTube, Google, Facebook і OpenStreetMap, а `<script>` — ні.

Що залежить від людей:

- Окремий обліковий запис кожному, хто працює з сайтом; пароль ніде більше не використовується й не пересилається в чатах. Коли людина перестає працювати з сайтом — «забрати доступ» у розділі «Обліковий запис».
- Двоетапна перевірка входу в кабінеті хостингу, у пошті, на яку він зареєстрований, і на GitHub. Хто має доступ до файлів хостингу, той має доступ до всього сайту.
- Резервна копія: раз на місяць (і перед великими змінами) завантажувати з хостингу теки `content/` і `uploads/` на комп'ютер. Історія правок в адмінці рятує від помилки редактора, але не від збою хостингу.
- Персональні дані: фото й прізвища дітей — лише за згодою батьків. Репозиторій на GitHub публічний і пам'ятає всі версії: видалене із сайту фото лишається в його історії.

## Що де лежить

- `content/` — увесь вміст у JSON. `content/.history/` — попередні версії кожного запису (останні 30), їх видно в адмінці в розділі «Історія змін». `content/.trash/` — видалені фото й PDF, зберігаються 30 днів. Обидві теки тримають дані в підтеці з випадковою назвою (`k-…`), щоб їх не можна було відкрити за прямим посиланням.
- `uploads/` — фото й документи. `uploads/thumbs/` — зменшені копії фото для списків; для нових фото створюються самі, для перенесених зі старого сайту — командою `python3 tools/make_thumbs.py`.
- `config/` — облікові записи й службові файли (не в git).

## Оновити статичну копію в `docs/`

```bash
python3 tools/export_static.py http://127.0.0.1:9600 docs
```
